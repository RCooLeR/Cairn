## Still open

All findings not explicitly listed as fixed, eliminated, contained, or partial above remain open. In particular:

- Server release-surface containment does not close the broader desktop request-budget finding BE-002 or create the authenticated remote architecture described by the review.
- BE-005 still needs the canonical global project/import-origin identity migration and resolver; its current conflict handling is intentionally fail-closed containment.
- BE-014 through BE-016 still need richer immutable request tokens and complete normalized effect/resource summaries even though unplanned creation paths are contained.
- BE-024's reliable mailbox is not an end-to-end fix until terminal/completion producers use the critical API and callers surface admission failure; durable replay/query remains separate work.
- BE-025 remains opt-in LAN-capable and lacks global listener, connection, bandwidth, and per-container quotas even though unsafe/unsupported bind semantics now fail closed.
- BE-031 through BE-036 remain open: helper image immutability/least privilege, live-volume consistency classification, metadata fidelity, daemon-side cancellation, failed-restore cleanup, and root-owned backup shutdown/pruning need separate designs. BE-030's output allocation/publication race is closed.
- BE-037 is constrained to an exact literal-loopback transport, but a malicious same-user loopback service can still receive/relay Agent context. BE-039's generic Docker/log redaction remains best-effort, and Cairn does not yet show the user an exact final outbound payload preview.
- BE-053 and BE-019 are bounded process-wide but still need per-client ownership, lease/deduplication, and disconnect reclamation before any multi-client surface is supported. BE-054 settings apply on startup/rebind; live hot reload remains an enhancement.
- BE-060 remains open for renderer filesystem APIs outside the newly contained Agent/import/log-export paths; a common OS-dialog grant/capability contract is still required.
- BE-064 still needs retention for audit, notifications, and update history. Update-check generation/history retention is now closed independently.
- BE-071 remains open for custom provider-install, backup, and update job stores.
- BE-081 does not claim arbitrary custom Dockerfile-frontend compatibility or persist a parser-version/error field; unsupported or invalid inputs are intentionally unresolved rather than guessed.
- BE-082 leaves a durable visible `started` row after a process crash or persistent post-write audit outage, but no startup/background reconciler finalizes that marker automatically yet.
- Docker exposes no atomic conditional-delete token for volumes. Cairn re-inspects exact scope/name/creation time/metadata under the runtime lock, but an external same-user actor can still recreate an indistinguishable same-name volume between the final inspect and Docker's delete call.
- Database files and new migration backups are scrubbed of legacy build-argument values. Pre-existing `.bak-*` files created by older versions are intentionally neither rewritten nor deleted automatically and require user-controlled backup rotation or manual removal.

Babel's App-size deoptimization note also remains as a tooling signal for the broader FE-047/FE-051 architecture work; FE-063's unit-test warning/error noise is closed.
