# Reliability review — 2026-08-30

Command examples use the current `src/` layout from the repository root. The recorded review results and executable identity below are preserved; this path update does not certify a new post-migration binary.

## Reproduced user reports

- Cairn displayed **Object disappeared / No interactive shell was found** for
  the healthy `rcooler-ollama` container. The Docker SDK's cloned HTTP transport
  installed TLS configuration that caused exec/hijack operations to bypass
  Cairn's WSL dialer. An SDK-level regression test reproduced
  `dial wsl+stdio: unknown network wsl+stdio` before the fix.
- Open WebUI was running and healthy when inspected. Windows received HTTP 200
  with `{"status":true}` from `http://127.0.0.1:3000/health`, and the browser
  rendered the sign-in page. No container recreation, data removal, credential
  change, or WSL reset was performed. Cairn's container drilldown retained old
  health/status metadata, independently of the working web service.

## Implemented fixes

| Area | Defect and correction |
| --- | --- |
| WSL terminal transport | Explicit HTTP/1 protocols prevent SDK transport cloning from enabling the TLS path that bypasses the custom dialer. |
| Exec cancellation | WSL/SSH and native socket exec-upgrade connections are tracked and closed on cancellation; established sessions remain independent of the opening RPC. One-shot hijacked reads now close on timeout. Native TCP and Windows named-pipe regressions cover the SDK path. |
| Shell detection | Transport, cancellation, and permission failures are preserved instead of being relabeled as a shell-less image. |
| Exec memory limits | One-shot terminal probes/file listings have a 4 MiB output limit and fail explicitly on overflow. |
| Terminal lifecycle | Duplicate opens are guarded; stale opens are closed; quick session exits cannot resurrect a tab; stale shell choices are reset. Backend writer channels are initialized before a session becomes visible to concurrent writes/shutdown. |
| Windows PTY handles | Process-handle ownership remains locked through termination checks; Wait releases the handle on failure as well as success. This prevents a concurrent close from acting on a recycled handle. |
| Terminal output | App-lifetime, bounded output capture retains early prompts and output received while navigating away. Empty events, byte count, chunk count, session count, and closed-session tombstones are bounded. |
| Inventory and details | Read-only RPC deadlines prevent lost responses from latching loading flags indefinitely. Partial snapshots and last-good data remain available; intentional sequential WSL reads are preserved. |
| Object refresh events | Mixed resource kinds and IDs are coalesced without dropping earlier invalidations. Async refresh callbacks are serialized with one merged trailing event, preventing busy-daemon events from continually invalidating slow WSL reads. Continuous event traffic has a maximum debounce wait. |
| Container details | Status/health/port rows use current inventory instead of the initially loaded inspect summary. |
| Command execution | A one-second post-exit/cancellation pipe-drain bound prevents descendants holding stdout/stderr from extending command waits indefinitely; context errors are retained. |
| Provider detection | Interrupted/incomplete probes no longer overwrite known provider state with false missing-component diagnoses. |
| Provider/runtime consistency | Status probes preserve the selected provider; initial/fallback selection is rebound explicitly. Successful provider lifecycle operations still synchronize the runtime when completion auditing fails. Starting an inactive provider does not unnecessarily tear down the active runtime. |
| Compose health | Unhealthy services take priority over starting services regardless of input/map iteration order. |
| Project jobs | Successful mutations followed by audit-write failure still emit terminal job events and refresh notifications. |
| Port forwarding | Start/stop are serialized, and connections accepted/dialed during shutdown are closed even when they arrive after the cleanup snapshot. Canceled reconciliation results cannot remove current forwards. |
| Metrics lifecycle | Start/stop are serialized and workers registered before startup is published. Late inventory responses cannot add watchers after shutdown's cleanup snapshot. |
| Other read-only UI flows | Dashboard, notifications, audit, settings, restore previews and forwarding status have bounded reads. Superseded dashboard responses cannot overwrite newer state. |
| Agent cancellation | Stopping a completed-tool follow-up releases its UI busy state even if the model/bridge request never settles. |
| Cleanup UI | Prune selections cannot change underneath an executing cleanup. |
| Backup cleanup | Errors releasing expired-plan resources are logged rather than silently discarded. |

Existing confirmation, runtime-scope, file-edit quarantine, credential
containment, and backup identity protections were preserved.

- Every Go package was exercised with the race detector on the reviewed tree.
  The complete run passed every package except a new Windows PTY test's
  assumption about `GetExitCodeProcess` on a non-process handle. The test now

  `go -C src test -race -count=1 ./internal/terminal` then passed. No race was reported.

## Coverage limits and workspace notes

Native Linux/macOS desktop smoke tests, long-running Linux-only chaos/soak
tests, and destructive live backup/restore/update workflows were not performed
on the user's workloads. Desktop startup was inspected directly; further
automated desktop clicks were obstructed by other tool windows. Mock-backed
release UI tests and real WSL terminal integration provide the complementary
flow checks. This review fixes the confirmed defects, not a guarantee that no
latent bug can exist in any environment.

Windows process creation intermittently stalled during validation. Checks were
completed serially, using a persistent diagnostic shell where needed. No
security settings or WSL configuration were changed, and no OS restart was
forced.

Unrelated deletions under `col-review/` and `fable/` appeared in the worktree
during this task; they were not made or reverted by this review.
